# 读懂 SoCPK Comparison Lab：如何从芯片与续航数据中得出可靠结论

[English](reading-the-dashboard.md) | 简体中文

2026-09-26 · @Jun Zhi

[SoCPK](https://socpk.com) 公布的能效数据是移动硬件领域最有参考价值的资料之一：在主板端测得的 CPU、GPU 功耗–性能曲线，以及数十款在售手机的续航结果。不过，这个网站一次只展示一张图表，而我真正关心的问题大多需要把几颗芯片放在同一坐标系里，或者在某个具体功耗下从曲线上读出数值。

GKWSocpk 是我的一个个人项目。它把这些结果抓取为 CSV 快照，再放进一个本地对比仪表盘。本文讲的是如何用好这个仪表盘：每个数字从哪里来，每张图表怎么读，Analysis lab（分析实验室）算的是什么，以及数据在哪里就不足以支撑结论了。

如果你只是想把它跑起来，[README](../README.zh-CN.md) 里有安装说明。简单来说，先用四个抓取脚本采集快照，然后运行 `python socpk_web.py`。下文默认仪表盘已经在浏览器中打开。

文中的例子来自我在 2026 年 9 月 23 日采集的快照。SoCPK 每次新增或修订结果，你看到的数字都会随之变化。

![仪表盘](images/dashboard.png)

## 数字从哪里来

在信任一个数字之前，先弄清楚它的来源。

| 数据 | 来源 | 一行数据代表什么 |
| --- | --- | --- |
| CPU 曲线（GB6、GB7） | SoCPK 多核能效页面 | 芯片曲线上的一个公布点：主板功耗、分数 |
| CPU 曲线（SPEC 2026 INT/FP） | SoCPK SPEC 页面 | 某颗芯片**单个核心**的一个点 |
| 手机 GPU | SoCPK，3DMark Steel Nomad Light | GPU 曲线上的一个点 |
| 笔记本 GPU | SoCPK，3DMark Time Spy Graphics | GPU 曲线上的一个点 |
| 电池 | SoCPK 续航测试 5.0 | 一款手机：续航时间和电池标称容量 |
| 手机处理器、屏幕、刷新率 | GSMArena，由 `--auto-soc` 查询 | 附加在电池数据行上的元数据 |
| 元数据修正 | `battery_metadata.json`，人工审核 | 对芯片组、屏幕和刷新率字段的修正 |
| 实测可用容量 | 极客湾（Geekerwan）自行实测，写在代码中 | 约 27 款手机的参考叠加层 |

有三点需要记住：

1. **曲线上的点是 SoCPK 公布的数值，其中一部分是上游拟合所得。** 仪表盘从不重新拟合。需要两个点之间的数值时，它只在两点之间画一条直线，也从不在公布范围之外外推。
2. **电池排名只使用电池标称容量和 SoCPK 的续航时间。** GSMArena 查询和人工修正只决定一款手机归入哪个处理器分组、屏幕规格是多少。极客湾的实测值会画在图上，但从不改变任何排名。
3. **每份快照都会保留。** 采集脚本从不覆盖文件。重新运行时会在原文件旁写入类似 `battery_results_20260923T014112457065Z_1.csv` 的文件，仪表盘会加载每个系列中最新的那一份。页面顶部右侧的说明会列出实际加载的文件。如果在仪表盘打开期间采集了新数据，点击 **Reload data** 即可。

## 熟悉界面

### 标签页就是数据集，数据集之间不能混用

顶部的每个标签页对应一个 CSV 系列：

| 标签页 | 基准测试 | 一个配置项（profile）是… |
| --- | --- | --- |
| GB6 MULTI | Geekbench 6 多核 | 一颗芯片 |
| GB7 MULTI | Geekbench 7 多核 | 一颗芯片 |
| SPEC26 INT | SPEC CPU 2026 整数 | 芯片的一个核心，例如 *A19 Pro — Everest (V4)* |
| SPEC26 FP | SPEC CPU 2026 浮点 | 芯片的一个核心 |
| GPU | 3DMark Steel Nomad Light（手机） | 一颗 GPU |
| LAPTOP GPU | 3DMark Time Spy Graphics | 一颗笔记本 GPU |
| BATTERY | 续航测试 5.0 | 一款手机，或某款手机在特定系统版本下的结果 |

分数只能在同一个标签页内比较。GB6 分数和 GB7 分数的单位不同，手机 GPU 和笔记本 GPU 跑的也是不同的 3DMark 测试。仪表盘有意把它们分开，如果一个 CSV 混入了两种 CPU 基准测试，它会直接拒绝加载。

当前标签页会记录在网址中，所以 `http://localhost:8765/#Battery` 或 `#SPEC%20INT` 会直接打开对应数据集，可以加入书签。`[` 和 `]` 切换标签页，`/` 跳到搜索框。

### 选择要对比的对象

- **Compare** 用于选择图表。每个 CPU 和 GPU 标签页有三张图表，BATTERY 有五张。
- 左侧的**配置项列表**决定画出哪些对象。单击可切换选中状态，Shift+单击可选择一个范围。
- **Top 5** 按*当前图表的排名指标*选出前五名，而且会一直保持生效。如果在开启 Top 5 的状态下从 *Performance curve* 切换到 *Efficiency curve*，选中的对象会变，因为两张图表的排名依据不同。想在多张图表之间保持同一组芯片，请手动单击选择。
- **All shown** 选中搜索框和筛选条件当前允许显示的所有对象。**Clear** 清空选择。
- 在 SPEC 标签页中，**Filter cores** 可按核心分组（Super、Large、Medium、Small）或核心名称筛选列表。这样就能只对比各芯片的超大核，不让能效核挤满图表。

### 每张图表的组成部分

- **统计卡片。** *Profiles* 显示"已选 / 可用"。*Data points* 统计所选对象背后的公布数据点数量。*Current leader* 显示按当前图表指标表现最好的已选对象。
- **排名面板。** 图表右侧的排名按标题中的指标对已选对象排序，↑ 或 ↓ 表示哪个方向更好。列表较长时，在面板上滚动即可。
- **更优角落。** 青色小三角形标出结果更优的角落，图表下方的一行说明会解释这个角落的含义。
- **悬停。** 鼠标悬停在数据点上可查看精确数值。单击数据点会把它的名称固定显示在图表下方的说明中。
- **Efficiency reference。** 这个开关会在合适的图表上绘制虚线参考线，图表下方的说明会解释当前显示的参考线。下文会逐个图表介绍这些参考线。

### 性能曲线（Performance curve）：每个功耗预算能换来多少性能

建议从这张图开始看。可以纵向读（"在 5 W 下哪颗芯片分数最高？"），也可以横向读（"要跑到 9,000 分，哪颗芯片需要的功耗最低？"）。越靠左上越好。

排名依据是**峰值分数**，通常就是最高公布功耗下的分数。它告诉你性能上限，却说明不了能效。一颗芯片在这里排第一，可能只是因为 SoCPK 把它跑到了 18 W。

开启 **Efficiency reference** 后，图表会画出从原点出发的虚线射线。同一条射线上的每个点每瓦分数相同。粗射线穿过所选对象中能效最高的点；在 CPU 标签页中，浅色射线分别表示该能效的 50%、25% 和 12.5%。GPU 标签页使用更细的间隔：87.5%、75%、62.5% 和 50%。如果一条曲线向下弯曲、越过较低的射线，说明它随功耗上升在损失能效；它在某个功耗下穿过的是哪条射线，就能看出损失了多少。

### 能效曲线（Efficiency curve）：每颗芯片的最佳区间

这张图显示每瓦分数与功耗的关系。大多数芯片在低功耗时能效最高，负载加重后稳步下降。排名依据是**峰值每瓦分数**。

对这个排名要谨慎。峰值能效通常出现在最低的公布功耗处，而各芯片的起测功耗并不相同。在 GB6 快照中，A20 Pro 的最低点在 0.52 W，达到 3,212 分/W。骁龙 8 Elite Gen 5 的曲线从 1.37 W 开始，峰值为 1,847 分/W。这个差距有一部分是真实的，另一部分只是因为其中一颗芯片在曲线更低的位置被测量过。要在同等功耗下更公平地比较，请看下一张图表和 Analysis lab。

### 能效 vs 分数（Efficiency vs score）：在同等性能下比较

这张图显示能效与分数的关系。它回答的是"两颗芯片提供相同性能时，谁更省电？"，而这通常正是"哪颗芯片能效更高？"这个问题的本意。越靠右上越好。两条曲线相交时，各自在交点分数的一侧能效更高。

### 稀疏曲线是最常见的陷阱

在 GB6 上，SoCPK 为骁龙 8 Elite Gen 5 公布了 120 个点，为 A20 Pro 只公布了三个：0.52 W、2.18 W 和 13.50 W。在图表上，A20 Pro 的"曲线"就是两段直线，其中第二段跨越了 11 W 以上。

真实的功耗–性能曲线是向下弯曲的，在这样的曲线上取两点连成的直线会落在曲线下方。因此，当你读取 Apple 芯片在公布点之间的数值时，仪表盘很可能**低估**了它。这不算错误，因为仪表盘只展示公布过的数据，但落在这类长间隔里的比较只是很弱的证据。Analysis lab 会为每个估算值报告间隔的大小。

这些标签页还有几个限制：

- **主板功耗**是 SoCPK 的测量口径，图表假定它在同一基准测试内是一致的。
- **短时间的基准测试**反映不了持续性能或受散热限制后的性能。
- **SPEC 配置项是单个核心。** 比较 *A19 Pro — Everest* 和 *Snapdragon 8 Elite Gen 5 — Oryon V3 L* 比较的是两颗超大核，并不能说明整个 CPU。

## 曲线的 Analysis lab

图表下方的 **Analysis lab** 面板针对当前选择进行分析。在 **Analysis** 中选择模式，选择一个 **Baseline**（基准）配置项，再设置目标值。单击任意表格的列标题即可排序。

### 同等功耗 / 同等性能（Equal power / performance）

设置 **Power target (W)** 和 **Target score**。第一张表给出每颗芯片在该功耗下的分数。第二张表给出每颗芯片达到目标分数所需的最低功耗，以及相对基准节省了多少功耗。

以下是 GB6 快照在 5 W 下的结果：

| 配置项 | 5 W 下的分数 | 依据（Evidence） |
| --- | --: | --- |
| 骁龙 8 Elite Gen 5 | 7,539 | 由两个相邻很近的公布点估算 |
| 天玑 9500 | 7,500 | 由两个相邻很近的公布点估算 |
| A20 Pro | 7,010 | 估算：2.18 W / 5,015 → 13.50 W / 13,025；**间隔 11.32 W** |
| A19 Pro | 6,355 | 跨越 11.0 W 的间隔估算 |

如果直接读，A20 Pro 在 5 W 下落后安卓旗舰约 7%。**Evidence** 列说明了这个结论为什么站不住：A20 Pro 的数值是一条跨越 11 W 的直线，中间没有任何实测点。"跑到 9,000 分需要多少功耗"也有同样的问题（A20 Pro 7.81 W，骁龙 8 Elite Gen 5 6.82 W）。

这一列的作用就是不让这种间隔被掩盖。写着 *Published* 的，是真实公布的点。写着 *Estimated* 且间隔很小的，数值可靠。间隔达到好几瓦的，请把数值当作下限来看。

如果目标值超出了某颗芯片的公布范围，表格会显示 *Outside published range*，不会去猜。如果一条曲线不止一次穿过目标分数，表格报告的是达到该分数的最低功耗。

### 功耗权衡（Power trade-offs）

这张表给出每颗芯片达到**自身**峰值分数 80%、90%、95% 和 100% 所需的功耗，以及最后 10% 性能额外消耗的瓦数。最后这一列往往是整个实验室里最能说明问题的数字：一颗芯片为最后 10% 的性能多花 6 W，说明它被调校到远超高效区间的位置。需要注意，每个百分比都是相对于该芯片自身峰值而言的，所以各行之间并不是同等性能的比较。

### 公布点前沿（Published-point frontier）

这个模式把所选芯片的所有公布点汇总在一起，只保留非支配点：没有其他已选点能以不高于它的功耗达到至少相同的分数。图和表会显示功耗范围的每一段分别由哪颗芯片占据。前沿只使用公布点，从不用估算值把它们连起来。

### 基准 / 代际对比（Baseline / generation comparison）

把较老的芯片设为 **Baseline**，例如把 A19 Pro 作为 A20 Pro 的基准，或把骁龙 8 Elite 作为骁龙 8 Elite Gen 5 的基准。对其他每颗芯片，实验室会报告：

- **共同功耗范围**，即两条曲线都有数据的区间。区间之外不做比较。
- **目标功耗下的提升**，以相对基准的百分比表示
- **等分交点**，即两条曲线相交的功耗。例如，一颗新芯片可能在 4 W 以下领先、4 W 以上落后。
- 整个共同范围内提升百分比随功耗变化的图

稀疏曲线的警告在这里同样适用。只要任一曲线上有一段很长的直线，这段直线两端之间的百分比就只是估算。

## 读懂电池图表

每款手机有两个测量输入：SoCPK 续航测试 5.0 的**续航时间**，以及取自电池标称信息的**容量（Wh）**。其他数值都由这两个推导而来：

- **平均功耗（W）** = 容量 ÷ 以小时计的续航时间。越低越好。
- **能效（min/Wh）** = 以分钟计的续航时间 ÷ 容量。越高越好。两个指标说的是同一件事，只是单位不同：60 ÷ 平均功耗 = min/Wh。

例如：

| 手机 | 续航时间 | 容量 | 平均功耗 | 能效 |
| --- | --: | --: | --: | --: |
| iPhone 18 Pro Max | 637 分钟（10.62 h） | 21.06 Wh | 1.98 W | 30.2 min/Wh |
| 荣耀 WIN RT | 726 分钟（12.10 h） | 36.88 Wh | 3.05 W | 19.7 min/Wh |

荣耀的续航更长，而 iPhone 的功耗低了约三分之一。两种说法都成立。电池标签页的大部分功能，都是为了把这两个问题区分开。

这些数字描述的是**整台手机**：屏幕、基带、内存、软件和芯片。它们是根据额定能量估算出的平均功耗，并没有单独测量芯片。得出芯片层面的结论时，需要带上这个前提。

### 续航时间 vs 容量（Runtime vs capacity）

![续航时间 vs 容量](images/battery-runtime-vs-capacity.png)

这张图显示续航时间（小时）与电池容量的关系，按续航时间排名。它回答的是"哪款手机最耐用？"，所以大电池自然占优，这对这个问题来说是合理的。

虚线参考线表示：在所选手机中能效最高者的功耗下，每种电池容量能获得的续航时间。如果选中了 iPhone 18 Pro Max，这条线就是 `续航时间 = 容量 ÷ 1.98 W`。按荣耀的 36.88 Wh 计算，结果是 18.6 h，远高于它实际的 12.1 h。手机与这条线之间的垂直距离，就是它相比最高效的手机少了多少续航。这条线是一个恒定能效的假设情景，不是对任何真实手机的预测。

### 能效（Energy efficiency）

![能效](images/battery-energy-efficiency.png)

这张图布局相同，续航时间以分钟为单位，但按**每 Wh 分钟数**排名。在这里小手机可能胜过大手机，因为电池容量被除掉了。当问题是"哪款手机对电池的利用最好？"时，请看这个排名。

### 平均功耗（Average power draw）

![平均功耗](images/battery-average-power-draw.png)

这张图显示平均功耗与电池容量的关系，按功耗从低到高排名。越靠右下越好：功耗低、电池大。这里的参考线是**帕累托前沿**。带圆圈的手机满足这样的条件：所选手机中没有另一款同时拥有更大的电池和更低的功耗，虚线把它们连起来。任何位于这条线左上方的手机，都会在两方面同时被线上的某款手机超过。

### 极客湾实测容量

约 27 款手机会用空心菱形显示极客湾实测的可用容量，并用虚线与 SoCPK 数据点相连。鼠标悬停在菱形上，可以看到实测与标称 mAh 的对比、差额，以及按实测容量计算的功耗和 min/Wh。请把它当作背景信息：排名、参考线和处理器平均值都仍然基于电池标称容量。可以通过 **Geekerwan measured capacity** 关闭菱形显示。

### 处理器平均值

如果快照是用 `--auto-soc` 采集的，左侧面板会多出一个 **Processors** 标签页，并出现另外两张图表：

| SoC 平均功耗 | SoC 平均能效 |
| --- | --- |
| ![](images/battery-soc-average-power.png) | ![](images/battery-soc-average-efficiency.png) |

每个处理器的点是使用该处理器的手机的简单平均，每款手机只计一次。鼠标悬停在点上可以看到背后有几款手机。这个数量最为关键：只有一款手机的处理器平均值就是那款手机本身，并不代表整个芯片系列。无法可靠识别芯片组的手机不计入平均值，但仍会出现在设备图表中。

在设备图表中，**Overlay average lines** 会为每个已选处理器画一条带标签的线，方便看出哪些手机高于或低于其芯片的平均水平。

## 电池的 Analysis lab

### 按处理器分组的手机功耗（Phone power grouped by processor）

这个模式给出每个已选处理器的手机功耗**均值、中位数和范围**，以及涉及几个品牌。它还有一张 **Remove one brand at a time** 表，依次去掉每个品牌后重新计算均值。如果去掉某一个品牌后，某个处理器的平均值变化很大，说明这个平均值主要反映的是该品牌手机的表现。

**Brand**、**屏幕尺寸**和 **Listed refresh** 筛选只作用于这个面板。它们适合做粗略的同类比较，比如只看 6.3 英寸的手机。当对应筛选开启时，缺少该项规格数据的手机会被排除。"Listed refresh"是规格表上的刷新率，不是测试时实际使用的刷新率。

最后一张表列出每台设备及其来源信息，包括 `battery_metadata.json` 中的修正及其出处。

### 续航 / 代际对比（Runtime / generation comparison）

这个模式把每款手机与基准之间的续航差异拆成两个因素：

```
续航比 = 容量比 × 功耗倒数比
```

以 iPhone 18 Pro Max 为基准，荣耀 WIN RT 的结果如下：

| | 数值 |
| --- | --: |
| 容量比 | 1.751（电池大 75%） |
| 功耗倒数比 | 0.651（功耗是其 1.54 倍） |
| 续航比 | 1.751 × 0.651 = **1.140** |

荣耀的续航长 14%，是因为电池优势抵消了功耗劣势还有余。这张表把这个权衡明确摆出来，而不是藏在一个续航数字里。

**Common battery (Wh)** 回答的是反过来的问题：假设每款手机的平均功耗不变，在相同容量下各自能用多久。按 20 Wh 计算，iPhone 可以用 10.1 h，荣耀可以用 6.6 h。这是一个假设情景，不是测量结果。

做代际对比时，把较老的机型设为基准，并自行匹配产品线和尺寸，例如用 iPhone 17 Pro Max 对比 iPhone 18 Pro Max。两者之间的软件和其他硬件仍然存在差异。

## 导出数据

### 图表和表格

- **Export chart** 把当前图表连同排名面板保存为 PNG 或 SVG。
- **Export analysis CSV** 保存当前 Analysis lab 模式下的所有表格。文件开头记录了数据集、数据加载时间、你的设置、已选配置项、源文件和计算方法，方便日后追溯这些数字。

### 原始 CSV

`snapshots/` 中的快照是普通的 UTF-8 CSV。曲线文件使用统一的格式：

| 列 | 含义 |
| --- | --- |
| `CPU` / `GPU` | 芯片名称 |
| `Board_Power_W` | 主板功耗（瓦） |
| `GB6_Multi_Score`、`GB7_Multi_Score`、`SPEC2026_INT_Score`、`SPEC2026_FP_Score`、`GPU_Score` | 分数，列名对应基准测试 |
| `Efficiency` | 分数 ÷ 功耗 |
| `Benchmark` | 仅 CPU 文件；必须与分数列一致 |
| `Core`、`Core_Group`、`Core_Variant` | 仅 SPEC 文件：核心名称、分组（super/large/medium/small）以及 p/e 类型 |

电池文件每行一款手机：

| 列 | 含义 |
| --- | --- |
| `brand`、`model`、`os` | 机型信息。品牌使用 SoCPK 原始语言（例如 荣耀），除非采集时使用了 `--brand-lang en` |
| `minutes`、`hours` | 续航时间 |
| `capacityWh` | 电池标称容量 |
| `avgPowerW`、`avgPowermW`、`minPerWh` | 按上文方法推导 |
| `delta_vs_best_*_pct` | 在功耗、min/Wh 和续航时间上与快照中最佳手机的百分比差距（0 即为最佳） |
| `chipset`、`soc`、`cpu`、`gpu`、`screen_size_in`、`refresh_hz` 等 | 使用 `--auto-soc` 时获取的 GSMArena 元数据 |
| `soc_device_count`、`soc_avg_*` | 采集时计算的处理器平均值 |
| `metadata_review`、`metadata_source`、`metadata_reviewed` | 人工审核说明（如有） |
| `url`、`spec_url` | 来源视频和规格页面 |

有一个细节：`battery_metadata.json` 中的审核修正是在仪表盘加载数据时应用的，从不写回快照。因此，直接用原始 CSV 算出的处理器平均值可能与仪表盘略有不同。

### JSON 和 Python

仪表盘运行时，`GET /api/data` 会在一个 JSON 文档中返回页面绘制所需的全部内容：每个数据集、配置项、曲线点、电池配置项和处理器平均值，并且已经应用了修正。`POST /api/reload` 会从磁盘重新构建它。

```sh
curl -s http://localhost:8765/api/data \
  | jq '.datasets[] | select(.key=="Battery") | .socAverages[] | {soc, deviceCount, powerW}'
```

不启动服务器、在 Python 中获取相同的数据：

```python
from pathlib import Path
from socpk_data import load_collections
from socpk_web import build_payload

collections, warnings = load_collections(Path("."))   # 每个系列的最新快照
gb6 = collections["CPU"]                               # pandas DataFrame，原始数据点
payload = build_payload(collections, warnings, Path("."))  # 仪表盘看到的数据
```

数据集的键名为 `CPU`、`CPU GB7`、`SPEC INT`、`SPEC FP`、`GPU`、`Laptop GPU` 和 `Battery`。

## 引用数字前的简短检查清单

1. **比较是否在同一个标签页内？** 分数不能跨基准测试使用。
2. **这个数值是公布的还是估算的？** 看 Evidence 列，任何超过一两瓦的间隔都要警惕。
3. **比较的是同等功耗、同等性能，还是各自的峰值？** 这是三个不同的问题，芯片在每个问题上的排名可能都不一样。
4. **对电池来说，问题是关于续航还是关于功耗？** 最耐用的手机和最省电的手机可能不是同一款。
5. **处理器平均值背后有几款手机？** 只有一款手机，就只是个例。
6. **说的是手机还是芯片？** 电池数据衡量的是整台设备。

这个仪表盘的设计目标，就是让上面每个问题都能在几次点击内得到答案。
